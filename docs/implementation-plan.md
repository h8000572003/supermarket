# 實作計畫：便利商店模擬 MVP

詞彙以 [CONTEXT.md](../CONTEXT.md) 為準；架構決策見 [ADR 0001](adr/0001-simulation-core-separated-from-rendering.md)、[ADR 0002](adr/0002-save-only-at-prep-phase.md)。

## 架構

```
src/
├── sim/          純 TypeScript 模擬核心，不 import pixi / react / DOM
│   ├── catalog/      商品、商品類別、設施定義（靜態資料）
│   ├── store/        網格、設施擺放、走道驗證
│   ├── inventory/    倉庫、格位、批次、報廢
│   ├── economy/      資金、進貨單、固定支出、售價
│   ├── agents/       顧客、店員的狀態機
│   ├── pathfinding/  網格 A*
│   ├── clock/        營業日階段、遊戲時鐘、倍速
│   ├── report/       每日結算彙整
│   ├── progress/     口碑、里程碑、破產
│   ├── rng.ts        可設種子的亂數
│   └── game.ts       Game：對外唯一入口（commands + tick + events）
├── render/       PixiJS 等角場景：讀取 sim 狀態、轉成 sprite
├── ui/           React 面板：進貨單、結算、擺設工具列、速度控制
├── audio/        訂閱 sim 事件播放音效
├── persistence/  localStorage 存讀檔（只存準備階段快照）
└── main.tsx
assets/           Kenney 素材（CC0）與佔位色塊
```

### 模擬核心的介面（深模組）

外界只透過三件事與 `Game` 互動：

- **Commands**：`placeFixture`、`rotateFixture`、`sellFixture`、`assignSlot`、`setSalePrice`、`submitPurchaseOrder`、`hireStaff`、`fireStaff`、`openStore`、`setSpeed`。準備階段以外呼叫會被拒絕並回傳原因。
- **`tick(dtMs)`**：以固定步長推進模擬（例如 100ms 遊戲內步長，倍速只改變每幀執行幾步）。
- **Events / 唯讀狀態**：`CustomerEntered`、`SaleCompleted`、`CustomerAbandoned`、`Restocked`、`DayEnded`、`MilestoneReached`、`Bankrupt`… 供 render、ui、audio 訂閱；不回寫 sim。

`render` 與 `ui` 只讀狀態、發 command，絕不直接改 sim 內部資料。

## 開發階段（每階段都可遊玩、可驗證）

### M0 — 專案骨架
- Vite + TS + React + PixiJS + Vitest + ESLint；`npm run dev / test / build`。
- `sim/rng.ts`（seeded，如 mulberry32）與第一個測試。
- PixiJS 畫出 12×10 等角地板與入口；React 疊一個空白 HUD。
- **完成條件**：瀏覽器看到等角地板；`npm test` 綠燈。

### M1 — 店舖與擺設（準備階段）
- `catalog`：一般貨架、冷藏櫃、收銀台的定義（尺寸、格位數、容量、價格）。
- `store`：網格佔用、旋轉 4 向、正面 / 取用格計算、出售 50% 回收。
- `pathfinding`：網格 A*；**走道驗證**——擺放後入口必須能到達每個取用格，否則拒絕。
- UI：設施工具列、點擊放置、旋轉、出售；不合法位置顯示紅色預覽。
- Render：等角座標轉換、深度排序（依 x+y）、Kenney Furniture Kit 等角圖（缺圖用色塊）。
- **測試重點**：堵住收銀台的擺放被拒；旋轉後取用格改變；出售退款金額。

### M2 — 商品、庫存與進貨
- `catalog`：5 類別、約 12 項商品（建議售價、進貨價、最低訂購量、冷藏需求、保存期限）。
- `inventory`：倉庫與格位皆以**批次**儲存、先進先出；冷藏類別只能指定到冷藏櫃格位。
- `economy`：進貨單（運費、最低訂購量）、隔日開店前送達倉庫；售價設定。
- UI：進貨單面板、格位指定、售價調整。
- **測試重點**：FIFO 取貨順序；冷藏限制；送達時機；資金不足拒單。

### M3 — 時鐘與營業日循環
- `clock`：準備階段 → 營業時段（07:00–23:00，1x ≈ 4 分鐘）→ 每日結算；暫停 / 1x / 2x / 4x。
- 營業時段鎖定所有 command（只能觀察）。
- 打烊時扣固定支出（租金 + 日薪），讓當天的每日結算包含它。
- 準備階段開始時：送達進貨、**報廢過期批次**（計入當天的帳）。
- UI：時鐘、速度控制、「開店」按鈕。
- **測試重點**：階段轉換順序；營業中 command 被拒；跨日報廢。

### M4 — 店員與補貨
- 雇用 / 解雇（同質、日薪）；日薪計入固定支出。
- 店員在營業時段沿路徑移動：格位陳列庫存低於補貨門檻且倉庫有貨 → 走到倉庫取貨 → 走到該格位的取用格補貨。
- 收銀派工的優先序先保留介面（「收銀台有人排隊 > 補貨」），M5 有顧客後接上。
- Render：店員小人（佔位）沿路徑移動、搬貨中的狀態。
- **測試重點**：低於門檻才補；倉庫無貨時不補；先進先出；多位店員不重複補同一格。

> 順序說明：先做店員再做顧客，是為了讓顧客上線時架上已有商品可買，M5 才能在畫面上驗證。

### M5 — 顧客與收銀
- 來客生成：時段曲線（早 / 午 / 晚三峰）× 口碑倍率。
- 顧客狀態機：進店 → 依購物清單逐類別找格位 → 價格判定是否拿取 → 前往收銀台排隊 → 結帳 / 耐心耗盡放棄 → 離店。
- 收銀：店員優先處理排隊（打斷補貨）；一次服務一位顧客、固定處理時間；無店員的收銀台不運作。
- 滿意度計算：缺貨、價格、排隊時間。
- Render：顧客小人（佔位）沿路徑移動、頭上狀態圖示（找不到 / 不耐煩）。
- **測試重點**：同一種子重現同一營業日；全缺貨時空手離開；耐心耗盡不產生營收；零店員時顧客最終全數放棄。

### M6 — 每日結算、口碑與進度
- `report`：營收、進貨成本、報廢損失、固定支出、淨利、來客 / 成交 / 放棄（缺貨 vs 排隊）、各類別銷量、缺貨排行、口碑變化。
- `progress`：口碑由近幾日平均滿意度平滑更新；資金連續 3 日為負 → 破產；3–5 個里程碑解鎖鮮食、日用品、第 2 台冷藏櫃等。
- 起始只開放飲料、零食、泡麵。
- UI：結算面板、里程碑提示、破產畫面。
- **測試重點**：結算數字與當日事件一致；破產判定；里程碑解鎖。

### M7 — 存檔與音效
- `persistence`：準備階段開始時自動存檔；快照含設施、格位指定、批次、資金、口碑、店員、進度、日數、RNG 狀態；載入回到準備階段。加上版本號欄位。
- `audio`：Kenney CC0 音效——UI 點擊、收銀成交、顧客放棄提示；全域靜音開關（偏好存 localStorage）。無背景音樂。
- **測試重點**：存→讀→狀態相等；舊版本存檔處理。

### M8 — 平衡與收尾
- 調整起始資金（約可買 3–4 陳列櫃 + 1 收銀台 + 2 店員 + 首張進貨單、撐 3 天虧損）、租金、日薪、價格敏感度、耐心、來客曲線。
- 以 seeded headless 模擬跑「固定策略 × 30 天」檢查平衡（不需要畫面）。
- 部署為靜態網站（GitHub Pages）。

## 測試策略
- `sim/` 以 Vitest 為主，覆蓋上列測試重點；全部 deterministic（seeded RNG、固定步長）。
- `render/`、`ui/` 只做手動驗證，不寫單元測試。

## 素材
- Kenney Furniture Kit 的等角渲染圖（下載後確認是否附 4 方向 PNG）；缺的物件（收銀台、零食架）與角色先用程式繪製色塊。
- 渲染層維護「設施 / 角色 → sprite」對照表，換素材不動 sim。
- 若素材不足再考慮：把 Kenney 3D 模型預渲染成等角 sprite sheet（另開 ADR）。

## 之後的階段（不在 MVP）
員工能力 / 士氣 / 裝備、廣告、多地點與分店、店面擴建、衝動購買、手機觸控、背景音樂。
