# 03: 派工到換貨中的格位

**What to build:** 對換貨中、尚未下架的格位派工時，最近有空的店員先去下架，再把新商品補滿，完成後才清除派工標記。換貨中的格位即使舊商品還滿架也能派工；派工的「倉庫沒有貨」檢查改看換貨目標（新商品）。

規格：`.scratch/open-hours-changeover/spec.md`（使用者故事 21–23）

**Blocked by:** 01（換貨主流程）

**Status:** resolved

- [x] 舊商品滿架、換貨中的格位可以派工
- [x] 派工後店員先下架，接著補滿新商品，完成後標記清除
- [x] 倉庫沒有新商品時派工被拒並說明原因（即使倉庫有舊商品）
- [x] 沒有換貨的格位派工行為不變（既有派工測試通過）
- [x] `npm test`、`npm run lint`、`npm run build` 通過

## 實作決策

- 換貨中的格位派工：`dispatch()` 不檢查「已補滿」與「沒有指定商品」，「倉庫沒有貨」看換貨目標。
- 換成不指定商品（目標為 null）的格位也能派工，意思是「現在就去下架」；下架後格位沒有指定商品，標記隨即清除。
- 派工的下架由最近有空、不在處理派工的店員認領（`StaffAgent.assignDispatchClearOut`，`onDispatch = true`），因此派工的優先序（高於一般下架與補貨、收銀台派工不搶）適用。下架後格位成為一般補貨候選，由既有的派工流程補滿新商品。
- 下架前標記保留（舊商品滿架也不清除）；只有在沒人認領、且換貨目標在倉庫沒有貨時清除。倉庫沒有新商品時不派人去下架。
- 派工補貨中（尚未取貨）的格位開始換貨：放下該補貨（不再補舊商品），標記保留，改成先下架再補滿新商品。已拿著貨的照常上架。
- 取消換貨派工：還沒取下的下架放下，換貨照常由店員以一般下架完成。
