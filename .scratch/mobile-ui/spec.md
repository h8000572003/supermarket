# 規格：手機操作與介面優化

Status: ready-for-agent

詞彙以 `CONTEXT.md` 為準；架構決策見 ADR 0001（模擬核心與畫面分離）。本規格只改 `src/ui`、`src/render`、`src/styles.css`、`index.html`，`src/sim` 不動。

## Problem Statement

遊戲目前只為桌機的滑鼠與鍵盤設計，在手機上幾乎無法正常遊玩：

- 直向時，HUD 佔掉約 20% 高度，工具列與提示又佔約 20%，店面只剩中間一小塊；橫向時，HUD 加工具列蓋掉約一半畫面，店面縮得更小。
- 「商品與進貨」表格有七個欄位，超出螢幕寬度，「倉庫」以後的欄位被切掉，面板也壓到 HUD。
- 縮放只能用滾輪；不能雙指縮放，也不能平移。
- 放置設施靠滑鼠 hover 預覽，觸控時手指一按下去就直接扣錢放下，看不到取用格是否被擋、朝向對不對。
- 「右鍵／Esc 取消」與「R 旋轉」在手機上無法使用，提示文字卻仍寫著這些操作。
- 等角格子在手機上約 24px，手指點不準；櫃子的圖往上方突出，點櫃子上半部會選到後面的地板格。
- 各面板外觀不一致，顏色、間距、圓角寫死在各處。

## Solution

整套介面一起重整，手機以直向為主，橫向也能用。桌機的操作方式（hover、右鍵、R、Esc、滾輪）全部保留。

- **兩個判斷分開**：版面依寬度（≤ 720px 用手機版面），操作依指標類型（`pointer: coarse` 用觸控流程）。觸控平板拿到寬版版面加觸控操作；桌機縮小視窗拿到窄版版面加滑鼠操作。
- **鏡頭**：雙指縮放、單指拖曳平移（移動超過約 8px 才算拖曳）、「重設視角」按鈕；直向時預設縮放讓店面寬度貼齊螢幕。
- **觸控放置**：點地板只顯示預覽，並出現浮動按鈕「✓ 放置／⟳ 旋轉／✕ 取消」，按 ✓ 才扣錢放下；移動設施也走同一套流程。
- **精簡 HUD**：約 44px 的狀態列，加上一顆主要按鈕；次要按鈕收進「⋯」選單。
- **底部工具列**：一排；店員的雇用與解雇移到抽屜裡。
- **面板**：一般面板改成底部抽屜，「商品與進貨」和每日結算改成全螢幕頁面；商品表改成卡片。
- **視覺**：現有的深色半透明風格整理成 CSS 變數，統一各面板外觀；配色與美術不變。

## User Stories

### 鏡頭與點擊

1. 身為手機上的店長，我希望用雙指縮放店面，這樣我能放大看清楚格子再擺設。
2. 身為手機上的店長，我希望用單指拖曳平移店面，這樣放大後還能看到店的其他角落。
3. 身為手機上的店長，我希望手指只是稍微晃動時仍算點擊，而不是被當成拖曳，這樣點選不會失靈。
4. 身為店長，我希望有一個「重設視角」按鈕，這樣迷失位置時能一鍵回到整間店置中。
5. 身為直向手機上的店長，我希望一開始店面就貼齊螢幕寬度，這樣不需要先手動放大。
6. 身為店長，我希望點到櫃子的圖本身就能選取它，而不是只能點它底下的地板格。
7. 身為桌機上的店長，我希望滾輪縮放照舊，也能用滑鼠拖曳平移。

### 放置與移動設施

8. 身為手機上的店長，我希望點地板時先看到設施的預覽（可放為綠、不可放為紅），這樣不會一點就扣錢。
9. 身為手機上的店長，我希望預覽時再點別的格子就把預覽移過去，這樣能慢慢找位置。
10. 身為手機上的店長，我希望預覽旁有「✓ 放置／⟳ 旋轉／✕ 取消」按鈕，這樣不需要鍵盤和右鍵。
11. 身為手機上的店長，我希望預覽位置不可放時 ✓ 按鈕停用，並看到原因。
12. 身為手機上的店長，我希望移動既有設施也是「預覽、確認」的流程。
13. 身為桌機上的店長，我希望左鍵直接放置、R 旋轉、右鍵／Esc 取消的操作不變。
14. 身為觸控裝置上的店長，我不希望看到「左鍵、右鍵、R、Esc」之類用不到的提示。

### HUD 與工具列

15. 身為手機上的店長，我希望 HUD 只用一條細列顯示天數、時間與資金，這樣店面有更多空間。
16. 身為店長，我希望準備階段的「開店」按鈕一直看得到，營業中則換成倍速切換。
17. 身為店長，我希望「目標」「音效」「新遊戲」收進「⋯」選單，這樣不會誤觸「新遊戲」。
18. 身為店長，我希望點一下狀態列就能展開口碑、店內人數與今日營收。
19. 身為店長，我希望準備階段的工具列是一排：選取、一般貨架、冷藏櫃、收銀台、商品與進貨、店員。
20. 身為店長，我希望「商品與進貨」按鈕上仍顯示在途進貨單數的徽章。
21. 身為店長，我希望在「店員」抽屜裡雇用或解雇店員並看到日薪，這樣不會在工具列上誤按解雇。
22. 身為店長，我希望營業中的工具列只有「商品與進貨」和派工說明。
23. 身為店長，我希望操作提示只佔一行，不會把工具列擠高。
24. 身為店長，我希望提示訊息固定出現在工具列上方，3 秒後自動消失，錯誤訊息用紅色。
25. 身為橫向手機上的店長，我希望狀態列在上方、工具列在右側直排，這樣店面保有完整高度。

### 抽屜與面板

26. 身為手機上的店長，我希望選取設施後，旋轉／移動／出售、格位設定或派工從底部抽屜打開，高度約半個畫面。
27. 身為手機上的店長，我希望抽屜打開時鏡頭自動平移，讓被選取的設施露在抽屜上方。
28. 身為手機上的店長，我希望點地板空白處或把抽屜往下拉就能關閉抽屜。
29. 身為橫向手機上的店長，我希望抽屜從右側滑出，寬度約 40%。
30. 身為手機上的店長，我希望「目標」面板也是底部抽屜。

### 商品與進貨

31. 身為手機上的店長，我希望「商品與進貨」以全螢幕頁面打開，左上角有返回鍵。
32. 身為手機上的店長，我希望每個商品是一張卡片，收合時就看到名稱、類別、倉庫／在途數量與售價。
33. 身為店長，我希望卡片上的售價低於建議售價時顯示綠色、高於時顯示紅色，這樣一眼就知道定價狀態。
34. 身為店長，我希望點卡片展開後，用 −／＋ 步進器調整售價與訂購量，並看到進價與建議售價作為參考。
35. 身為店長，我希望步進器中間的數值仍可點開，用數字鍵盤直接輸入。
36. 身為店長，我希望用頁首的類別分頁切換商品，這樣不必一路往下捲。
37. 身為店長，我希望未解鎖的商品排在最後並顯示為灰色。
38. 身為店長，我希望頁面底部固定一條「小計＋運費＝合計｜下單」，捲動時也看得到。
39. 身為營業中的店長，我希望在展開的卡片裡開始限時特價，並在頁面裡下緊急叫貨。

### 每日結算與狀況

40. 身為手機上的店長，我希望每日結算是全螢幕頁面，底部固定一顆「進入下一天」。
41. 身為手機上的店長，我希望狀況以底部抽屜出現且不能下拉關閉，這樣遊戲不會卡在暫停狀態。

### 瀏覽器與全站

42. 身為有瀏海的手機上的店長，我希望 HUD 與工具列不被瀏海與 Home 條蓋住。
43. 身為手機上的店長，我希望雙指縮放時只有店面縮放，整個網頁不會跟著放大，下拉也不會觸發重新整理。
44. 身為手機上的店長，我希望快速點兩下時不會放大網頁。
45. 身為手機上的店長，我希望所有可點擊的元素至少 44×44px。
46. 身為店長，我希望所有面板的外觀（顏色、間距、圓角、字級）一致。

## Implementation Decisions

### 範圍

- 只改介面層：`src/ui`、`src/render`、`src/styles.css`、`index.html`。`src/sim` 與存檔格式不動（ADR 0001、0002）。
- 不新增領域詞彙；`CONTEXT.md` 不變。

### 判斷方式

- **版面**：寬度 ≤ 720px（沿用現有斷點）時用手機版面；橫向用 `orientation: landscape` 加高度條件判斷。
- **操作**：`(pointer: coarse)` 時用觸控流程。在 `src/ui` 提供一個依 `matchMedia` 的 hook，例如 `usePointerCoarse()`，讓元件和 controller 都讀同一個來源。

### 鏡頭（`src/render/scene.ts`）

- 在現有的 `userZoom` 之外，新增平移偏移 `pan`；`layout()` 改成「置中 + pan」。
- 用 pointer events 追蹤多指：兩指時縮放，以兩指中點為縮放中心；單指移動超過約 8px 時轉為拖曳，之後不觸發 `click`。
- 平移範圍要有限制，店面不能被拖出畫面外。
- 直向時，`fitZoom` 改為依寬度貼齊（具體係數在實作時用截圖調整）。
- 對外提供 `resetView()`，以及「讓某個設施露在畫面某區域內」的平移 API，供抽屜呼叫。

### 點擊判定

- 點擊時先檢查是否點到設施 sprite 的範圍（依 zIndex 由前往後），點到就選取那個設施；沒點到才回到地板格判定。

### 放置流程（`controller` / `interaction`）

- 觸控模式下，`click(cell)` 在放置／移動模式中只更新預覽位置，不提交。
- 新增 `confirmPlacement()`；`rotate()` 與 `cancel()` 沿用現有的。
- 浮動按鈕定位在預覽格附近，需要把格子座標換算成螢幕座標，由 render 提供。

### 版面元件

- 新增共用的 `BottomSheet`（可設定能否下拉關閉、高度；橫向時改從右側滑出）與 `FullScreenPage`（返回鍵、底部固定列）。
- HUD 拆成 `StatusBar` 與 `MoreMenu`。
- 工具列加入「商品與進貨」與「店員」入口；「店員」用 `BottomSheet`。
- 商品卡片頁為 `StockPanel` 的窄版版面，共用同一份訂單狀態與送出邏輯；寬版維持表格。
- 新增共用的 `Stepper`：− 數值 ＋，數值欄位使用 `inputmode="numeric"`。

### CSS

- 在 `:root` 定義顏色、間距、圓角、字級與觸控目標的變數，各面板改用這些變數。
- 加上 `env(safe-area-inset-*)`、`touch-action: none`（畫布）、`overscroll-behavior: none`。
- `index.html` 的 viewport 加上 `viewport-fit=cover`。

## Testing Decisions

- 既有的 `npm test`、`npm run lint`、`npm run build` 都要通過。
- 純邏輯另外寫單元測試：拖曳門檻判定、平移範圍限制、雙指縮放中心換算、sprite 點擊判定。
- 每張 issue 都用 Playwright（Chromium 位於 `/opt/pw-browsers`）截三種尺寸的圖驗收：iPhone 13 直向、iPhone 13 橫向，以及 1440×900 桌機。觸控相關的 issue 用 `hasTouch` context 驗證手勢。

## Out of Scope

- PWA（manifest、加入主畫面、全螢幕啟動）。
- 震動回饋。
- 店面、設施與人物的美術。
- 遊戲規則、數值平衡與存檔格式。
