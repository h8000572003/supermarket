# 01: 垃圾與對麻煩派工（麻煩機制的第一條完整路徑）

**What to build:** 建立麻煩的共通機制，並以垃圾作為第一種麻煩，從模擬到畫面一次打通。顧客走過走道時有小機率掉垃圾；垃圾在場時來客速率 ×0.95，與它同時在場過的顧客離店時扣一次滿意度。店長點擊垃圾就是派工（共用 `MAX_DISPATCHES = 2`），最近有空的店員走過去、約 1 遊戲分鐘清掉，然後恢復自動工作。店員不會主動清。打烊時全部清除。場上畫出垃圾與醒目圖示，出現與清掉時播放音效。

規格：`.scratch/nuisances/spec.md`（使用者故事 1–11）

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] `sim/nuisances/` 以資料定義麻煩種類；`Game` 提供唯讀的在場麻煩清單
- [ ] 顧客走過走道格時以種子亂數小機率掉垃圾，結果可重現
- [ ] `DispatchTarget` 新增 `nuisance`；派工、取消派工、名額共用（滿了回傳 `dispatch-full`）
- [ ] 店員處理麻煩的任務：走過去、停留處理時間、移除麻煩、恢復自動工作；處理期間不收銀、不補貨
- [ ] 沒有派工時店員不處理麻煩
- [ ] 來客速率乘上在場麻煩的倍率，多個疊乘，處理後恢復
- [ ] 顧客離店時，每個同時在場過的麻煩扣一次滿意度
- [ ] 打烊時清除麻煩與相關派工；存檔不變
- [ ] 新增麻煩出現、處理完成的 `GameEvent`；音效
- [ ] 場景畫出垃圾與圖示（處理中有不同樣式）；點擊判定能點中麻煩並派工，再點一次取消，名額滿時提示
- [ ] 既有平衡守門測試通過（必要時調整掉落機率）
- [ ] `npm test`、`npm run lint`、`npm run build` 通過
